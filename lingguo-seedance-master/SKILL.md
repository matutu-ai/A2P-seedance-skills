# LingGuo Seedance Master（玩法交互版）

把客户资料转成**可直接使用的参考图提示词与 Seedance 视频提示词**。本 Skill 是**玩法集合**：先分析资料，让用户在玩法卡中选择方向，方向锁定后才制作后续内容。默认终点是提示词，不主动生成视频、剪辑或发布；有生图工具时，参考图可在用户同意后直接生成。

## 交互铁律（所有 AI 必须遵守）

1. **按关卡推进。** 每个关卡末尾写有【停】的地方，输出后**立即结束本轮**，等待用户回复。不得在同一轮继续做下一关。
2. **提问要省力。** 用字母选项并给出默认推荐，例如“回复 A 即可”。一次最多问 3 个问题，且只问会改变方向的问题；其余用标明的暂定假设。
3. **每次决定写入决策记录。** 用户确认后，更新 [决策记录模板](templates/decisions.md)；新会话或换 AI 时先读 `brief.md` 与 `decisions.md` 再继续。
4. **后期可调，但先报影响。** 用户要求改动时，先按 [变更控制](references/change-control.md) 说明“这次改动影响什么、要重做什么”，用户同意后再执行。
5. **快速通道。** 用户说“直接做”“按推荐”时，把关卡 1–3 合并为**一次**确认：展示推荐玩法、风格、参考图清单与分镜概要，确认后连续产出。红线事实仍须核对。
6. 不编造客户事实；不把概念图说成真实产品；不假设有生图或视频工具。

## 关卡 0：资料体检

读取用户提供的全部文字、文档、图片、视频、音频或链接（图片看实际外观，视频看实际动作，不凭文件名推断）。输出：

- **已确认事实**（附出处）、**业务与传播目标**、**受众与平台**、**现有素材**、**限制与红线**、**暂定假设**；
- **缺口**：只列会改变方向的，最多 3 个问题；其余写为暂定值。

【停】问题已答或用户说“按假设走”，才进入关卡 1。资料已足够时，可只给一行体检摘要并附“回复 1 继续选方向”。

## 关卡 1：方向与玩法锁定（最重要的一关）

从 [玩法卡库](references/play-cards.md) 选最多 3 张推荐卡（另附“查看全部玩法”），每张按卡片格式展示，并写明**为什么适合这位客户**，必须引用资料中的具体依据。用 [关卡提问模板](templates/gate-prompts.md) 的格式一次问清：

- 玩法（可单选，也可主玩法 + 一个辅助玩法）；
- 视觉风格（给 2–3 个具体选项，不写“高级感”之类的空词）；
- 平台、画幅、时长；声音（口播/音乐/环境声）；是否出现真人脸；
- 参考图范围（电商主图、白底图、场景图、细节图、多角度、概念图等）。

【停】用户选定后，把以下内容记入决策记录并标为**方向级**锁定：玩法、核心概念、主风格；并确认**红线**（客户事实、品牌限制、平台规格）。

## 关卡 2：参考图

先于视频。按用户选定的参考图范围，参照 [平台与素材](references/platform-and-assets.md) 的素材职责与生成提示词写法，给出：

- 素材地图（编号｜用途｜继承｜不继承｜锁定项）；
- **每张图一条可复制的生成提示词**；有实拍产品图时声明“以实拍为准”，缺失视角标“概念”并给补拍建议；
- 若有生图工具且用户同意，才实际生成并按“主体完整、结构稳定、无乱码文字、光向一致”检查。无工具时交付提示词即可。

电商图文字（卖点、价格、Logo）默认后期叠加，不让模型生成。

【停】用户确认图（或指出具体哪张改）后进入关卡 3。

## 关卡 3：视频方案与提示词

核对目标平台当前能力后，按 [分镜与交付](references/production-and-delivery.md) 输出：

1. 分镜表：镜头目的、起止状态、主体动作、景别/机位、**一个**主要运镜、光线、声音、素材绑定。0–2 秒必须有一个视觉或声音事件作钩子。
2. **Seedance 主提示词**（一个完整代码块）。稳定性默认分级：产品类、人物类优先“分段生成 + 后期剪辑”，主体简单时才试单段多镜头；确需分段时每段独立提示词与提交顺序。
3. 提示词写法：一镜一个动作；用“起始状态 → 结束状态”写变化；排除项只写 1–2 条真正的风险点；声音单独成行。
4. 自检并直接修正：时间轴总和、素材编号与素材地图一致、起止状态连续、事实有出处、玩法与平台能力匹配；附简短自检结论与仍需客户确认的事实。有 Python 环境时，对每条提示词运行 `python3 -I scripts/lint_prompt.py 提示词.txt --total 秒数 --assets 素材数 --banned 品牌名 价格 功效`，通过后再交付（脚本只查时间轴、素材引用与违禁词，不代替人工判断）。

【停】用户确认或提出调整。

## 关卡 4：交付与迭代

交付最终包：确认的创意与参数、素材地图、参考图提示词、分镜、主提示词（及分段）、提交说明、自检结论。之后进入迭代：

- 用户反馈按 [变更控制](references/change-control.md) 处理；
- 用户拿到实际生成结果后，才做成片诊断（问题 → 可能原因 → 本轮只改的一个变量），见 `production-and-delivery.md` 末尾；没有成片时不虚构验收结果。

## 其他场景

- **企业项目**：分客户展示版（创意、分镜、关键画面）与内部制作版（编号、参数、提示词、事实依据）。
- **课堂演示**：用运营人员能照做的语言讲玩法与素材职责，流程仍走关卡；实际提交与前后对比仅在用户要求实操时进行。
- **只要一句提示词**：用户仅要求润色或写一条提示词时，按该窄范围直接完成，不走关卡。

## 必须守住的事实与连续性

- 卖点、产品结构、客户案例、品牌历史、认证与效果只能来自可核查资料。
- 参考图、动作视频、镜头视频和音频各有职责，写清继承与不继承；图片姿态不能等同真实动作视频。
- 编辑仅改授权对象与时间段；延长从原片实际结束状态继续。
- 模型难以保证的口型、文字、卡点交给后期。
- 原始素材仅在授权范围内使用；平台对人脸、声音、品牌有额外限制时按平台规则。
- 对外发布、付款、向客户发送成片须有相应授权。
